# Connection implementations

Current public layouts (2026-10-20): Timeline and Overview. Overview uses `src/connections-view.js` and `src/connections-layout.js`, shared with the local experiment. The older renderer below remains archived. Personal review routes and the standalone experiment entry point are excluded from publication.

The preserved implementation is in `src/course-graph-view.js`, with obstacle routing in `src/connection-routing.js`, shared data helpers in `src/learning-graph.js`, and the graph styles in `src/course-detail.css`. Its model and geometry tests remain in `tests/learning-graph.test.js` and `tests/connection-routing.test.js`.

It keeps semesters in one horizontal row, reveals learning connections and the active note on hover or keyboard focus, opens course previews on click, and offers an explicit Focus connections / Show all semesters action. The renderer accepts `(detail, onPreview, closePreview)` and returns its element plus selection, semester-reveal, focus and destroy methods.

To restore it, import the renderer in Pathway Detail, add the layout to the model and toggle, mount/destroy it during layout changes, wire preview-close to clearSelection, and restore the preview's focus action. Remove its two renderer/router modules from the static build exclusion list. The learning-graph model remains active because Course Detail also uses the shared data.

The archived renderer is not imported or published. `timeLayout=connections` now selects the newer Overview implementation; legacy `timeLayout=years` links fall back to Timeline.

## Local mind-map experiment

The separate route `?view=connection-experiment&id=pathway-01` explores a different interaction without changing Pathway Detail. Run the normal local server and open that route directly. The student selector supports every demo pathway.

Click a course (or activate it with Enter/Space) to expand its direct connections over the semester grid. Background courses retain their original content, appearance and positions; a soft blur and reduced contrast separate them from the foreground. No empty placeholder blocks replace the courses. A local white veil supports legibility without a surrounding gray frame, border, or panel shadow. The overview becomes inert while expanded so keyboard navigation and assistive technology use only the readable foreground controls. Clicking empty space or the background restores all course content and interaction; a drag does not dismiss. Hover and keyboard focus alone do not open the map. Dependencies advance left to right; if the screen cannot accommodate the chain at normal card size, the whole graph flows downwards instead. Reduced-motion preferences skip fading; reduced-transparency and higher-contrast preferences use an opaque reading area.

Layout follows relationship depth, keeping a course in a later layer than every visible prerequisite. Independent siblings stack vertically, ordered by their actual course dates; same-term siblings are aligned by their neighbours to reduce crossings. Columns do not represent semesters. The card title remains the largest text and its actual term stays at bottom-left. Repeated calendar-year ranges, semester headings and selected-term context above the map are removed.

The diagram fits its available width by adjusting column gaps between 40 and 72 pixels, without scaling the 178px course cards or their text. All cards, including the selected course, use the same measured height. On screens that cannot fit the dependency layers with readable spacing, the entire graph flows downwards; siblings wrap within their level before the next level begins. Chronology is preserved along each connection, and dates within each sibling group remain ordered. Information surfaces are constrained to the same width budget. Large or narrow-screen graphs can need vertical page scrolling, but do not require horizontal panning.

Connections use straight segments and orthogonal elbows with small rounded corners. Every dependency advances to a later layer; dependent courses are never compressed into the same column. Routes use inter-column gutters, avoid course and information obstacles, and compare alternatives to minimize crossings. A white under-stroke separates remaining overlaps. The visible graph is transitively reduced: when A → B → C is visible, the redundant A → C arrow is omitted. This does not change source data or remove a unique relationship; hidden intermediate courses never justify suppressing an arrow. Human-Centered Systems and the full Database Design chain have zero-crossing regression coverage.

Branch hover only emphasizes edges. Every visible course uses the same compact width and height, including the selected course. Its description, course-detail link and optional gray student note appear in a separate floating information surface near that node. Placement searches nearby free space; the information rectangle participates in obstacle routing so arrows never run behind its content. The surface follows the selected node in keyboard reading order and is exposed through aria-details. It stays separate from the card and is not a fixed side drawer. Selecting a different node makes it the new center and shows its full ancestor/descendant chain. Activating the selected node again alternates full chain and direct connections; a small +/− cue and accessible expanded state indicate that action. There is no separate Full chain control. Reopening from the semester overview starts with direct connections. Clicking outside, Collapse connections, or Escape restores the grid; moving the pointer away does not dismiss the map.

Courses animate from their original on-screen positions into the map, and shared nodes move between layouts when selecting another center. Fixed visual copies avoid clipping while crossing between the grid and diagram. Interrupted transitions capture the current visible positions before accepting the next target; controls stay usable. Closing reverses the movement toward the semester grid. Reduced-motion preferences skip spatial movement. The original course regains focus on close, and the selected map course receives focus when opening or switching.

Implementation: `src/connection-experiment.js`, `src/connection-experiment-model.js`, and `src/connection-experiment.css`. Tests in `tests/connection-experiment.test.js` cover branch structure, forward dependency order, chronological sibling ordering, intersection detection, reachability-preserving reduction, equal card dimensions, width bounds, and obstacle-free routes around both courses and floating information for every demo root at desktop, tablet and phone widths. These modules and the local route are stripped from the public build by `scripts/build-site.mjs`. The older horizontal Connection renderer above remains preserved separately.

### Focused design review

The selected course stays compact and its information floats nearby; the real semester background remains softly blurred. The layout now prioritizes a readable relationship hierarchy within the viewport. It avoids both the excessive width of one-column-per-semester layouts and the looping arrows caused by packing dependent courses into the same column. Dates live on the courses, without additional date headers. Full chains may extend vertically when there is not enough screen area at the preserved card and text size. The shared renderer now powers public Overview. The standalone experiment route and all personal data stay local; user notes are unchanged.
