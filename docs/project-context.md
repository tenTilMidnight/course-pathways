# Course Pathways 项目背景

整理日期：2026-10-17（America/New_York）。这是供后续开发按需查阅的背景快照，不是固定的产品规格或开发计划。用户明确希望旧对话提供大致背景，不要求每次引用，也不要求后续决策完全基于旧对话。

## 平台的核心意图

让课程规划知识可以被复用。学生可以了解有相关背景、兴趣或未来目标的前人，如何跨学期选择和组合课程，以及为什么这样选择；同时通过结构化比较，理解可替代课程之间的实际差异，减少反复搜索、逐个询问和自行拼凑信息的工作。

用户最终要做的是决定修哪些课程、如何安排顺序，以及这些选择如何适合自己的学业与未来方向。平台以学生分享的经历和课程信息支持这些决定。就业、研究生或 PhD、学术方向和兴趣探索，都出现在原始愿景中。

## 用户亲自描述的两条主线

1. **前人选课路径分享。** 学长学姐、上过课的学生或校友分享专业、逐学期课表、兴趣及其变化、最后的就业或学术去向。后来者可按相关背景和目标寻找参考。例如 CMU IS → PM 与 CMU IS → SWE 的选课侧重可能不同；希望走 PM 方向的新生可以参考前人的实际选择和理由。
2. **相似课程的结构化比较。** 对同一 requirement 下的替代课程，并排展示内容侧重、教学风格、项目与考试占比等 catalog 不容易表达的差异。上过课的学生、TA 或教授可以贡献课程特点和经验，帮助后来者判断适配性。

这两条主线来自《Figma文件导入方法》中以“我想打造的产品是”开头的用户消息，原文见文末。

## 后续讨论补充的背景

- **起步人群：** 用户在《修改文字部分》中明确说先做 Information Systems。后续 workbook 与 input sheet 讨论曾进一步聚焦 CMU IS 大二、大三、希望走 Product Management 方向的学生。这是曾讨论的首发切入点，不能据此排除更广的长期愿景。
- **路径的上下文：** 用户在《完善产品输入文档》中提出，课程应显示先修要求、它为路径贡献者满足了什么 major requirement，以及该人在什么学期完成了哪些要求；也设想在个人页面展示 requirement 与所修课程的对应关系。
- **课程页面与外部规划：** 用户在《完成产品概念原型》中明确指出独立课程页面和外部工具入口的缺失，并列出 Student-Contributed Course Pathways、Peer Pathway Search and Discovery、Relevant Pathway Filtering、Course-in-Context Insights、Similar Course Comparison 和 Course Planning Integration 六类能力。外部工具示例是 Stellic；具体集成方式尚未确认。
- **界面反馈：** 用户认为路径卡片直接列出大量课程编号会产生视觉疲劳，曾尝试将课程名称放在 hover 后显示；希望减少填充文案。对于匹配分数，用户只是认为值得考虑是否解释结果依据，未确认评分算法。收藏课程是用户认为有用的原型发现。
- **已有原型讨论：** 《Prototype课程规划Web应用》包含“进入 → 提供少量背景 → 筛选路径 → 查看学期时间线 → 查看课程 → 暂存候选课程 → 比较”的流程，并曾要求免注册探索。对话报告生成过 HTML 原型，但当前工作目录没有该原型，本次也未导入或验证其实现。
- **名称：** 原型阶段用户曾指定 Coursewise；后来的讨论又表示产品名称未确定。当前仅确定 GitHub 仓库名为 `course-pathways`，不据此锁定产品品牌。

## 后续开发如何使用这些材料

- 优先遵循用户当前的需求和新决定；历史原型和课程作业是参考材料。
- 先区分用户明确提出的想法、旧 AI 的建议和假设性的作业答案。特别是 Concept 2 / 3 的一些分析被明确标成假设草稿，不能当成实际测试结果。
- 课程比较、路径比较和收藏清单是不同的功能，不要因旧原型把它们混在一起。
- 旧讨论里的“27 天降到 14 天”“10 分钟形成 3–5 门候选课”“80% 有依据的选课”等包含提议指标或待核验口径，不能作为已证实的产品效果。
- 学生经历与去向提供参考，不足以证明某门课程导致某种职业结果。
- 首版范围、最终名称、技术栈、数据获取与授权、贡献与匿名方式，以及正式规划工具的连接方式，留到相关开发任务中再决定。本次只建立仓库与背景。

## 原始愿景摘录

来源：[Figma文件导入方法](https://chatgpt.com/c/6aa05675-73e8-83e9-8d7b-482b426e872f)，用户消息中以“接下来我要完成这个部分”引入的产品描述。保留用户的原始措辞；其中关于现有市场的判断是当时的想法，不是本次验证的竞品结论。

> 我想打造的产品是，我想要建立一个平台，让upperclassmen/上过课的人，可以分享他们的专业，本科每个学期的课表，他们的兴趣（比如本来感兴趣的事或者逐渐发现的自己的兴趣），并分享他们最后的去向（做了什么工作/做了什么领域的学术，等等），让后来者可以作为参考。例如，同样是CMU IS的学生，有的人最后去做了PM，有的人最后去做了SWE，那他们选的课的侧重肯定不一样。如果有后来的IS新生也想做PM，那如果之前的学长学姐有过从IS去当PM的，那如果他们能展示自己为自己规划的课表，就可以成为新生很好的参考，新生就不用每学期去搜找合适PM的课了。因为我可以想象，找自己合适的职业方向的课这件事，无数人都重复地做过一次，所以我认为这个也是可以address的重复劳动。

> 同时，这个平台我还想做第二件事，就是对比同个requirement下不同的课的信息。比如这个专业的某个requirement有三节可选的课，那这三节的侧重点是什么，授课风格如何，课程项目/考试占比之间的区别，往往是catalog里的course description无法表现出来的，一般都需要同学们/教授在论坛里发post介绍，而这些介绍不是所有的课都有，也很难汇集到一起，所以当有人要做决定的时候，还是要自己反复地去问upperclassmen和搜找信息。我就希望我这个平台同时还能有一个地方专门呈现相似课程的对比，就是上过这些课程的人或者TA、教授，可以描述某门课的特点，这样就可以一目了然地对比相似的课程。这个东西现在应该是没有的，因为现在往往只有以单个课程为单位的课程介绍、评分。
